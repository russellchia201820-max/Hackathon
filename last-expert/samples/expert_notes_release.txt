Notes from Priya (release manager), recorded before her parental leave:

The checklist is right but it's the bare minimum. Never release on a Friday after 2pm, whatever the checklist says. Thursday morning is the real slot because the on-call handover happens Friday at 5.

"CI is green" isn't enough. The payments integration test is flaky, it fails about one run in five. If that's the only red one, rerun it once. If it fails twice, it's real, stop.

Staging lies about the database. It's a week-old copy, so any migration that touches the orders table needs checking against the read replica first. Ask Tom for access, he's the only one who can grant it.

"Approval from the product owner" really means Sam, and Sam only reads Slack DMs before 10am. After that, email.

When you watch the dashboards, ignore the CPU graph, it always spikes after a deploy. The one that matters is checkout success rate. If it drops under 97% in the first ten minutes, roll back, don't debug live.

The rollback pipeline doesn't undo database migrations. For those there's a script in the ops repo, scripts/undo_migration.sh, and you need to run it before the rollback, not after.
